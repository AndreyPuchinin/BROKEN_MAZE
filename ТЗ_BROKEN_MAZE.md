# ТЗ Игры "BROKEN-MAZE" (Переработанная версия)

## 1. Интерфейс

1. Тема: темная

### 1.1. Меню настроек

2. **Кнопка вызова:** Иконка шестеренки (⚙️) в правом верхнем углу экрана.
3. **Панель настроек:** Выпадающая/выезжающая панель справа с возможностью прокрутки (если настроек много).
4. **Читкод отладки:** В меню настроек есть скрытое поле ввода. При вводе кода `ANDY_KYBIK_DEBUGGER` активируется режим отладки (debug mode).
5. **Динамическая генерация полей:** Количество полей настроек зависит от количества этажей:
   - a. Для каждого этажа — отдельное **поле (не шкала!)** % покрытия ребрами.
   - b. Для каждого этажа — отдельное **поле (не шкала!)** % покрытия циклами.
   - с. Для каждого этажа - отдельное **поле (не шкала!)** % разрывности
   - d. Для каждой пары соседних этажей (1↔2, 2↔3 и т.д.) — отдельное **поле (не шкала!)** % лестниц.
6. **Кнопка "Сгенерировать":** Пересоздает лабиринт с текущими настройками.
7. **Сохранение настроек:** Настройки сохраняются в `localStorage` между сессиями.

### 1.2. Кнопка паузы

8. Надпись **"Pause"** в левом верхнем углу экрана. При нажатии поле игры становится бледнее, посередине возникает окно паузы с кнопками:
   - a. Продолжить
   - b. Новая игра

### 1.3. Поле игры

1. Поле игры центрировано ровно посередине экрана. Объекты на нем тоже центрируются, будь они
   - при режиме отладки
   - или при режиме игры

#### 1.3.1. С ПК

2. **Основной вид:** 3D-рендер от первого лица (Three.js или аналог).
3. **Управление:** WASD/стрелки для движения/поворота. Движение происходит автоматически на один коридор в следующую ячейку лабиринта. Поворот — анимированный ровно на 90 градусов визуально.
4. **Переключение этажей (в отладке):** Колесико мыши переключает активный этаж (сверху над полем игры написано *"Используйте колесико мыши для навигации между этажами"*).

#### 1.3.2. С сенсорных устройств

1. **Два виртуальных джойстика:**
   - a. **Левый:** Вперед/назад (движение по коридорам, тоже автоматически на один коридор до следующей ячейки).
   - b. **Правый:** Вправо/влево (поворот камеры на месте, тоже автоматическая анимация на 90 градусов).
   - Нажатия **НЕ копятся**: если зажать кнопку, она начнет действовать лишь в момент конца анимации (ввод блокируется во время анимаций)
2. **Стиль:** Полупрозрачные, крупные.
3. **Адаптивность:** Джойстики появляются только на устройствах с touch-экраном.

### 1.4. HUD (Heads-Up Display)

1. **Нижняя панель** (скрываемая/возвращаемая нажатием на стрелку, которая видна даже при скрытой панели):
   - a. **Таймер:** Формат `ЧЧ:ММ:СС.мс` (от часов до миллисекунд). Работает даже при стоянии, но при паузе тормозится.
   - b. **Счетчик шагов:** Количество пройденных узлов.
   - c. **% повторов:** Процент шагов, сделанных по уже посещенным узлам.
   - d. **Текущий этаж:** Индикатор "Этаж X из Y".
2. **Кнопка скрытия HUD:** Позволяет убрать нижнюю панель для полного погружения.
3. **Маркеры старта и финиша:** Визуальные индикаторы (**S** и **F**) в 3D-пространстве. S должен отображаться исключительно для ячейки старта, F — для ячейки финиша!

### 1.5

1. **Размеры:** Если лабиринт оказывается больше по размеру, чем Поле игры - Поле игры получает внутренний размер и по бегунку справа и снизу.

## 2. Бекенд (Треугольная сетка)

### 2.1. Структура данных

1. **Треугольная сетка:** Каждый узел имеет 6 соседей.
2. **Многоярусность:** Граф не одноэтажный, а многоярусный. Каждый этаж — отдельная треугольная сетка, параллельная другим.
3. **Узлы:** Можно кодировать `x,y,floor`.
4. **Рёбра:** Разделяются на горизонтальные (внутри этажа) и вертикальные (лестницы между этажами).

### 2.2. Алгоритм генерации лабиринта

**Порядок генерации (критически важен!):**

1. **Остовное дерево для каждого этажа:** Ровно по одному древу на этаж! Алгоритм Прима (или DFS) гарантирует связность внутри каждого этажа.
2. **Добавление циклов:** Для каждого этажа отдельно, согласно его % покрытия.
3. **Добавление лестниц между ячейками, которые можно соединить вертикально:** Для каждой пары соседних этажей отдельно, согласно их % покрытия лестниц. Лестницы добавляются ТОЛЬКО между коридорами/ребрами! Лестница не должна соединять с пустотой! % покрытия расчитывается не для всего этажа, а лишь для их общей части.
За целое берутся узлы с такими координатами, чтобы и в верхнем, и в нижнем этаже к ним примыкали коридоры.
4. **Изъятие ребер:** пробежимся по всем критическим ребрам на данном этаже. Если ребро можно изъять и не разделить общий граф на всех этажах (а не только на текущем) на две компоненты (ребро не было критичным), его можно изъять. Но тогда меняется % покрытия ребер на этаже. Поэтому после изъятия необходимо добавить это ребро где угодно еще на этаже! Поцедуру нужно повторить столько раз, чтобы % разрывности на данном этаже оказался нужным. Таким образом мы эффективно (бежим не по всем ребрам на этаже - а лишь по локально критичным) добавляем интереса к построению графа на этаже: он может быть локально разрывным.
5. **Размещение старта и финиша:** Только после полной генерации всех этажей и лестниц! Только на общем древе, в одной и той же компоненте связности друг с другом! Это гарантирует, что старт и финиш всегда в одной компоненте связности. Хотя они могут находиться на разных этажах.

### 2.3. Метрики расстояния до финиша

1. **Минимальный путь (графовый):** BFS по рёбрам.
2. **Геометрический (евклидов):** Прямое расстояние в 3D-пространстве (игнорирует стены).
3. **Усреднённый:** (графовый + геометрический) / 2.

### 2.4. Гарантии

1. **Связность:** Старт и финиш всегда достижимы друг от друга.
2. **Дистанция:** Финиш на заданном расстоянии от старта (по выбранной метрике).
3. **Гибкость:** Старт и финиш могут находиться на разных этажах.

## 3. Фронтенд (Визуал лабиринта)

### 3.1. Визуал/отображение

#### 3.1.1. Основная иллюзия (90° вместо 60°)

1. **Визуальное искажение:** Треугольная сетка (60° между направлениями) рендерится как квадратная (90° между коридорами).
2. **Циклы:** Визуальный цикл вокруг "треугольной колонны" (минимальный цикл на треугольной сетке) = 3 поворота (270°), а не 4. Цикл вокруг 6-угольника = 6 поворотов (540°), а не 4.
3. **Движение:** Дискретное перемещение (snap-to-node) с плавной анимацией перехода между узлами.
4. **Поворот камеры:** Анимированное вращение. Реальный поворот на 60° рендерится как визуальный поворот на 90°.

#### 3.1.2. Проблема "преобладания правой/левой стороны"

**Суть проблемы:** В конце коридора игрок видит только 3 направления (Лево, Прямо, Право), но реальных доступных направлений — 5 (из 6, так как одно — обратный ход).

**Решение — два режима маппинга:**

1. **Режим "Лево-центричный":**
   - a. Лево = 1-й слева коридор
   - b. Прямо = 2-й слева коридор
   - c. Право = 3-й слева коридор
2. **Режим "Право-центричный":**
   - a. Право = 1-й справа коридор
   - b. Прямо = 2-й справа коридор
   - c. Лево = 3-й справа коридор

**Продолжение вращения:** При повороте на визуальные 180° виден не тот же коридор, а 4-й. При дальнейшем вращении на 90° — 5-й и 6-й (6-й = обратный ход).

#### 3.1.3. Цветовое кодирование

1. Каждая стена/коридор имеет свой цвет. Это создаёт визуальную разницу между коридорами и сбивает игрока с толку при ориентировании в "неправильном" лабиринте.

#### 3.1.4. Режим отладки (Debug Mode)

1. **Активация:** Только по читкоду `ANDY_KYBIK_DEBUGGER` в специальном поле в настройках.
2. **Визуализация "как на карте ТЦ":**
   - a. Все этажи отображаются слоями (сверху вниз).
   - b. Активный этаж — яркий, в центре экрана.
   - c. Неактивные этажи — сильно темнее, сверху/снизу.
   - d. Переключение колесиком мыши, над полем игры надпись *"Используйте колесико мыши для навигации между этажами"*.
3. **Отображение сетки:** Видны все узлы (точки) и все возможные рёбра (пунктир).
4. **Лестницы:** Оранжевые неполные вертикальные линии (только до середины между узлами на экране — чтобы было точно ясно, из какого узла идёт лестница).
5. **Путь до финиша:**
   - a. На активном этаже — ярко-зелёный пунктир.
   - b. На других этажах — бледно-зелёный пунктир.
   - c. Переходы между этажами — жирная зелёная неполная (такая же, как и лестница) вертикальная линия.
6. **Старт и финиш:** Маркеры **S** (синий) и **F** (красный) отображаются только на своих этажах. Если старт или финиш сейчас на неактивном этаже, они отображаются бледнее (как и весь этаж).

### 3.2. Управление

#### 3.2.1. С ПК

1. **Движение:** W/↑ — вперёд, S/↓ — назад. Дискретный переход между узлами с автоматической анимацией (возможно покачивание, которое можно переключить в настройках).
2. **Поворот:** A/← — поворот налево, D/→ — поворот направо. Анимация вращения.
3. **Лестницы:** Чтобы подняться/спуститься, нужно посмотреть на стену с лестницей и нажать вперёд.

#### 3.2.2. С сенсорных устройств

1. **Левый джойстик:** Вперёд/назад (движение).
2. **Правый джойстик:** Вправо/влево (поворот на месте).
3. **Лестницы:** Подъём (анимация) при наведении на стену с лестницей и нажатии вперёд.

### 3.3. Эффекты

1. **Покачивание при ходьбе (head bobbing):** Имитация шагов (можно отключить в настройках).
2. **Анимация поворота:** Плавное вращение камеры.
3. **Анимация перехода между узлами:** Плавное перемещение.

## 4. Настройки (Полный список)

### 4.1. Общие параметры

1. **Размер поля:** Ширина и длина в узлах.
2. **Количество этажей.**
3. **Метрика расстояния до финиша:** min / геометрический / усреднённый.
4. **Дистанция до финиша:** Число шагов по рёбрам.

### 4.2. Настройки для каждого этажа (динамически)

1. **% покрытия рёбрами:** 0–100% (отдельно для каждого этажа).
2. **Наличие циклов:** Вкл/Выкл (общая настройка применительно ко всем, + для каждого этажа по отдельности).
3. **% разрывности:** 0–100% (отдельно для каждого этажа)

### 4.3. Настройки для лестниц между этажами (динамически)

1. **% покрытия лестницами:** 0–100% (отдельно для каждой пары соседних этажей: 1↔2, 2↔3 и т.д.). Покрытие происходит не для всего этажа, а лишь для их общей части.
За целое берутся узлы с такими координатами, чтобы и в верхнем, и в нижнем этаже к ним примыкали коридоры.

### 4.4. Настройки визуала и управления

1. **Режим маппинга коридоров:** Лево-центричный / Право-центричный.
2. **Скорость анимации поворота.**
3. **Скорость анимации перехода между узлами.**
4. **Интенсивность покачивания (head bobbing).**

### 4.5. Отладочные настройки

1. **Читкод:** `ANDY_KYBIK_DEBUGGER` (активирует режим отладки, до него отображается автоматически сгенерированный уровень).
2. **Отображение сетки:** Вкл./Выкл. (Вкл. только в режиме отладки).
3. **Отображение пути до финиша:** Вкл./Выкл. (Вкл. только в режиме отладки).

### 4.6. Сохранения

1. **Автосохранение прогресса:** Позиция, этаж, время, посещённые узлы.
2. **Сохранение настроек:** Все параметры генерации сохраняются между сессиями.
3. **Кнопка "Сохранить игру".**
4. **Кнопка "Загрузить сохранение".**
5. **Кнопка "Новая игра".**

## 5. Дополнительные требования

### 5.1. Кроссплатформенность (за счёт HTML)

1. Игра должна открываться в любом браузере (Chrome, Firefox, Safari, Edge).
2. Поддержка ПК и мобильных устройств (iOS, Android).
3. Адаптивный интерфейс (HUD, джойстики, панель настроек).

### 5.2. Производительность

1. Оптимизация рендера для мобильных устройств.
2. Ограничение FPS при необходимости.
3. Ленивая загрузка этажей (если их много).

### 5.3. Доступность

1. Поддержка клавиатурной навигации в меню.
2. Контрастные цвета для маркеров старта и финиша.
3. Возможность отключить эффекты (покачивание, анимации) для пользователей с вестибулярными нарушениями.
